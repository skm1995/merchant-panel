# Project instructions

- Keep Docker configuration under `docker/`, grouped by service.
- Use Composer for PHP dependencies and commit `composer.lock` for applications.
- Every class, function, method, and behavior in application code must have PHPUnit unit tests covering its success and failure paths where applicable.
- Follow TDD: write a failing test for the expected behavior before implementing it, then implement the smallest change that makes the test pass, and refactor while keeping the tests green.
- Keep unit tests in `tests/Unit` and integration tests that exercise multiple application layers or external services in `tests/Functional`.
- Run functional tests and their Phinx migrations against the dedicated MySQL database `app_test`; keep the application database `app` for local development.
- Run both PHPUnit suites before considering a change complete; functional tests must use isolated test data and clean it up.
- Run the PHPUnit test suite before considering a change complete.
- Empty string literals are forbidden in code.
- Define string values used by code as constants instead of inline string literals.
- Enum methods are an exception: they may return plain string literals directly when those literals are the enum's behavior, such as status messages.
- Declare an explicit type on every `private` or `public` class constant, such as `string`, `int`, or `bool`.
- Prefer backed enums for public sets of values instead of public class constants.
- Represent HTTP response status codes with the backed `ResponseStatusEnum`; define status text through its `message()` method.
- Keep a controller's route path in that controller as a typed `public const string`; do not create a route enum for a single controller route.
- Use `/` directly in path strings; avoid concatenating path segments with `DIRECTORY_SEPARATOR` when a readable path format string is sufficient.
- All PHP code must follow PSR-12.
- Keep controllers as thin HTTP adapters: each action should only invoke the application service for that feature (for example, `AuthController` delegates to `AuthService`). Put request handling, response rendering, validation, persistence, session management, and business logic in services.
- Keep PHPStan at level 8 and PHP CS Fixer configured for PSR-12.
- Write commit messages using the scoped Conventional Commits format `<type>(<scope>): <description>`; every commit must include a lowercase scope.
- Keep the PHP runtime compatible with the PHP version declared in `composer.json`.
- Name directories under `src/` in the singular, such as `Controller`, `Model`, `Enum`, and `Core`. Directories outside `src/`, such as `views/`, may use plural names.
- Group feature-specific services and their related classes in singular feature folders, such as `src/Service/Auth`, using a matching namespace.
- Configure local development services through the root `compose.yaml` file.
- Manage database schema changes with versioned PHP migrations using Phinx; never edit a migration that has already been applied.
- Give each migration a descriptive name, make schema changes reversible where practical, and test migration-dependent behavior with PHPUnit.
- GitHub Actions must run unit tests, apply Phinx migrations to a MySQL service, and run functional tests against that service.
- Do not commit local environment files or secrets.
